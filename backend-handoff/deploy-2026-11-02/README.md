# نشر تعديلات الباك إند — 2 نوفمبر 2026

الحزمة دي بتفعّل 3 حاجات مستنية السيرفر:

| التعديل | قبل | بعد |
|---|---|---|
| **سبحة المتوفّى / المريض / الذكر الجماعي** | الموقع بيقول «محتاجة تفعيل من الباك إند» | السبح بتتعمل ويتشارك فيها بعدّاد واحد، ومعاها إحصائيات الموقع كله |
| **الاشتراك في النشرة** | الزائر بياخد 401، والموقع بيقول «بيتجهّز على السيرفر» | الاشتراك بيتسجّل pending ويتبعت إيميل تأكيد (بعد ضبط SMTP) |
| **المشاريع** | صفحة المشروع ناقصها حقول، والمشروع المقفول ظاهر للزوار | حقول الصفحة + `projects/by-slug/{slug}` + الزوار بيشوفوا النشط بس |

## التشغيل (5 دقايق)

1. ارفع فولدر `deploy-2026-11-02` كله على السيرفر في الـ home (من File Manager في Hostinger أو `scp`).
2. ادخل SSH وشغّل:

```bash
cd ~/deploy-2026-11-02
bash deploy.sh --check     # فحص بس — مش بيغيّر أي حاجة
bash deploy.sh             # النشر
```

## الحماية اللي في السكريبت

- **قبل أي تعديل** بياخد نسخة من الكود (`app routes database bootstrap config composer.*`) و**نسخة كاملة من قاعدة البيانات** في `~/backups/2026-11-02-<الوقت>/`، وبيتأكد إن الـ dump كامل. لو مش كامل بيقف.
- **مش بيكتب فوق شغل حد:** لو أي ملف هيتغيّر اتعدّل على السيرفر بعد 29 أكتوبر، بيقف ويقولك اسمه. (`FORCE=1` بيتجاهل الفحص ده، ومتستخدمهوش غير لو متأكد.)
- مش بيعدّل `routes/api.php` بإيده: المسارات الجديدة في ملف لوحدها `routes/api-2026-11.php`، والسكريبت بيضيف سطر `require` واحد في آخر `api.php` (ولو السطر موجود مش بيكرّره).
- بيعمل `php -l` على كل ملف، وبعدين `migrate` و`optimize:clear`، وبيتأكد إن المسارات اتسجلت.
- **لو أي خطوة فشلت بعد الباك أب، الكود بيرجع لوحده.**
- في الآخر بيجرّب الـ endpoints الجديدة ويطبع النتيجة.

## الرجوع

```bash
bash ~/backups/2026-11-02-<الوقت>/rollback.sh
```
بيرجّع الكود. أمر استرجاع قاعدة البيانات كلها مكتوب في آخر الملف، ومتستخدمهوش غير للضرورة لأنه بيمسح أي حاجة اتسجلت بعد النشر.

- **SMTP:** حط بيانات إيميل `info@elyusr.org` في `.env` (`MAIL_MAILER=smtp`، `MAIL_HOST`، `MAIL_PORT`، `MAIL_USERNAME`، `MAIL_PASSWORD`، `MAIL_FROM_ADDRESS`)، وبعدين:
